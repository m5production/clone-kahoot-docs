# 11. Конструктор квиза на узких экранах

Функция за пределами версии 1.0: адаптивная навигация конструктора квиза. Закрывает [GAP-18](08-gaps-and-backlog.md). Новые ID продолжают общую нумерацию: D-10–D-11, US-33, FR-88–FR-92, NFR-U7.

Статус — **Реализовано**: требования перенесены в документы 1–8 (US-33 → [документ 2](02-roles-and-user-stories.md), FR-88–FR-92 → [документ 3](03-functional-requirements.md), NFR-U7 → [документ 7](07-non-functional-requirements.md), GAP-18 → [документ 8](08-gaps-and-backlog.md)); этот документ остаётся спецификацией функции.

## 11.1 Проблема

Конструктор построен на фиксированной двухколоночной сетке (`grid-cols-[280px_1fr]`, `quiz-editor.ui.tsx`): слева список вопросов, справа шапка с названием и кнопкой запуска и форма вопроса. Адаптивных брейкпоинтов во фронтенде нет — Tailwind-утилиты `sm:`/`md:`/`lg:` в `src/` не используются. При ширине около 360–500 px:

- правая колонка сжимается до ~100 px: название квиза и кнопка «Start this quiz» обрезаются, карточка редактора и пустое состояние нечитаемы;
- сайдбар шириной 280 px занимает бо́льшую часть экрана, хотя нужен только для выбора вопроса.

Экран игрока пригоден для телефона (NFR-U5), конструктор — нет. Та же проблема у экрана ведущего живой игры (`grid-cols-[240px_1fr_240px]`) — вне объёма этого документа, см. GAP-19.

## 11.2 Решения владельца продукта

Приняты 21.11.2026.

| ID | Вопрос | Решение |
|---|---|---|
| D-10 | Как на узком экране переключаться между списком вопросов и редактором? | Нижняя панель навигации с двумя разделами — «Вопросы» и «Вопрос» — закреплённая на обеих вкладках (паттерн bottom app bar). |
| D-11 | Где разместить кнопку «Start this quiz»? | Расширенная FAB (иконка и подпись «Start this quiz») над нижней панелью у правого края; видна на обеих вкладках. |

Рассмотренные альтернативы:

- **Старт в шапке** — отклонено: на 360 px шапке не хватает места одновременно для названия и кнопки; липкие панели сверху и снизу вместе съедают высоту.
- **Старт внизу раздела «Вопросы»** — отклонено: строже по гайдлайнам Material (панель — только навигация), но запуск не виден с раздела редактора, где ведущий проводит бо́льшую часть времени.
- **Drill-down без панели** (список → редактор с кнопкой «назад») — отклонено: обзор вопросов требует лишнего касания на каждый переход, а постоянная панель даёт ориентацию «я внутри квиза».

Известный минус FAB — перекрытие контента в конце длинной формы — снимается нижним отступом контента (см. 11.4).

## 11.3 Пользовательская история

**US-33. Собрать и запустить квиз с телефона.**
Как ведущий, я хочу редактировать вопросы и запускать квиз с телефона, чтобы не искать компьютер для правок перед игрой.

- При ширине экрана меньше 768 px конструктор показывает один раздел за раз: список вопросов или редактор выбранного вопроса.
- Внизу закреплена панель с разделами «Вопросы» и «Вопрос»; активный раздел подсвечен.
- Нажатие на вопрос в списке открывает его в разделе «Вопрос»; «Add new question» делает то же самое для нового вопроса.
- «Start this quiz» всегда на экране в виде FAB; если квиз не готов, нажатие объясняет почему.
- Название квиза видно в шапке и доступно для переименования.

## 11.4 UX-спецификация

### Раскладка

- Порог: меньше `768px` (Tailwind `md`) — мобильная раскладка; `768px` и шире — текущая десктопная без изменений. Отдельная планшетная раскладка не проектируется.
- Мобильная раскладка сверху вниз:
  1. **Шапка:** ссылка «← Back to quizzes» и название квиза в одну строку с обрезанием троеточием; нажатие на название открывает переименование, как сейчас.
  2. **Контент:** активный раздел во всю ширину, прокручивается; нижний отступ контента — высота панели плюс FAB, чтобы конец формы не перекрывался.
  3. **Нижняя панель:** закреплена внизу, высота ~56–64 px плюс `env(safe-area-inset-bottom)`.
  4. **FAB:** поверх контента, над панелью, у правого края с отступом.

```
┌──────────────────────────┐
│ ←  Название квиза …      │  шапка
├──────────────────────────┤
│                          │
│   раздел «Вопросы»       │
│   или «Вопрос»           │  контент
│                          │
│                 ┌──────┐ │
│                 │ ▶ St │ │  FAB «Start this quiz»
├──────────────────────────┤
│ [Вопросы]   [Вопрос]     │  нижняя панель
└──────────────────────────┘
```

### Нижняя панель

- Два пункта одинаковой ширины: «Вопросы» (иконка списка) и «Вопрос» (иконка редактирования). «Вопрос» показывает номер выбранного вопроса («Вопрос 3»); без выбора — просто «Вопрос».
- Активный пункт выделен визуально и через `aria-current`; разметка — `<nav>`.
- На пункте «Вопросы» — бейдж с числом неготовых вопросов (скрыт при нуле); дублирует смысл предупреждающих иконок списка (FR-55).
- Зоны нажатия не меньше 44×44 px (NFR-U7).

### Раздел «Вопросы»

Переносит содержимое сайдбара: список «Question N» с иконками неготовности и кнопками изменения порядка, «+ Add new question» внизу списка. Ссылка «Back to quizzes» переезжает в шапку.

### Раздел «Вопрос»

`EditQuestionForm` и `DeleteQuestionButton`, как в правой колонке сейчас. Если вопрос не выбран — пустое состояние «Select a question on the Questions tab or add a new one».

### FAB «Start this quiz»

- Расширенная FAB: иконка запуска и подпись «Start this quiz». Не icon-only — без подписи назначение неочевидно.
- Позиция: `fixed` над нижней панелью у правого края; видна на обеих вкладках — запуск доступен из любого раздела.
- При неготовом квизе (BR-49) визуально приглушена, но остаётся нажимаемой (`aria-disabled`): нажатие показывает уведомление с причиной — тултип `title` на сенсорных экранах не работает (NFR-U6).
- Действие то же, что у десктопной кнопки: создание сеанса и переход в лобби (FR-60). Те же `data-testid` — `start-session-button`/`start-game-button`, чтобы не переписывать e2e-сценарии запуска.

### Поведение

- Выбор вопроса в списке и «Add new question» переключают на раздел «Вопрос» (FR-21).
- Удаление открытого вопроса возвращает на раздел «Вопросы».
- Раздел «Вопрос» без выбранного вопроса не блокируется — показывает пустое состояние.
- Выбранный вопрос сохраняется при переключении разделов и при переходе через брейкпоинт (изменение ширины окна).
- Активный раздел — локальное состояние страницы; адрес `/:gameId/admin` не меняется.

## 11.6 Замечания к реализации

- **Одна смонтированная раскладка.** Подход «отрендерить обе и скрыть одну» (`hidden md:flex`) дублирует `questions-list` и другие `data-testid` и монтирует `EditQuestionForm` дважды — ломаются e2e-локаторы и состояние формы. Раскладку выбирать через `matchMedia('(min-width: 768px)')`; хука `useMediaQuery` в коде ещё нет — положить в `shared/lib`.
- Разбивка `pages/quiz-editor/quiz-editor.ui.tsx`: десктопная и мобильная композиции плюс `quiz-editor.ui.mobile-nav.tsx`. Панель остаётся на уровне страницы; в `shared/ui` выносить не нужно, пока нет второго потребителя. FAB — в `features/active-game/start-session` как расширенный вариант `StartSessionButton` поверх того же `useStartSessionMutation`.
- Test ids (реестр `.devin/rules/test-ids.md`, строка «Quiz editor»): `editor-nav-bar`, `questions-tab`, `question-tab`; бейдж проверяется текстом внутри `questions-tab`. `start-session-button`/`start-game-button` переиспользуются — существующие e2e запуска не меняются.
- E2E: viewport 390×844 в отдельном сценарии или новый проект `mobile` с `devices[...]` в `playwright.config.ts` — сейчас единый `Desktop Chrome`. Сценарии: переключение разделов, добавление вопроса, причина недоступного запуска, запуск готового квиза.
- Иконки — `lucide-react`, как в остальном коде; FAB по-прежнему `Button`-подобный элемент с `aria-disabled`, а не `disabled`, чтобы нажатие показывало причину.

## 11.7 Критерии приёмки

1. На ширине 390 px конструктором можно пользоваться без горизонтальной прокрутки: список вопросов, форма с принимаемыми ответами, название, запуск.
2. Выбор и добавление вопроса открывают раздел «Вопрос»; удаление открытого вопроса возвращает к списку.
3. Неготовый квиз: FAB приглушена, нажатие объясняет причину; бейдж на «Вопросах» показывает число неготовых.
4. Готовый квиз: FAB запускает сеанс и открывает лобби; существующие e2e-сценарии запуска проходят без изменений.
5. На 768 px и шире интерфейс не изменился; e2e-сьют в десктопном viewport зелёный.

## Вне объёма

- Мобильная вёрстка экрана ведущего живой игры (GAP-19) и остальных страниц — отдельная работа.
- Общая навигация приложения на телефоне (главная, история): панель строится только внутри конструктора.
