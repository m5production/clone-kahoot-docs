# 7. Нефункциональные требования

Статусы объяснены в [README](../README.md#статусы). Требования версии 1.0 (NFR-S8–S10, NFR-P5–P6, NFR-R5–R7, NFR-U5–U6, NFR-O4) — в [целевых требованиях](09-target-requirements.md#99-новые-нефункциональные-требования); NFR-U7 перенесено сюда из [документа 11](11-mobile-quiz-editor.md) после реализации.

## Безопасность

| ID | Требование | Статус |
|---|---|---|
| NFR-S1 | Пароли должны храниться в виде хеша (например, bcrypt или argon2), а не открытым текстом. | Реализовано (переписывание бэкенда: scrypt-хеши, GAP-2) |
| NFR-S2 | Сервер должен проверять сессию пользователя в каждом защищённом запросе; токен сессии должен быть неугадываемым и недоступным скриптам страницы (`HttpOnly`, подписанный или случайный токен). | Реализовано (непрозрачный случайный токен, в базе — хеш; уточнено D-9/NFR-S8) |
| NFR-S3 | Изменять, удалять и запускать квиз должен только его ведущий. | Реализовано (`getOwned` на REST, проверка роли на WS-командах; GAP-3) |
| NFR-S4 | Игроки не должны получать правильность ответов до их показа. | Реализовано (этап 4a: правильность только в `ANSWERS_REVEALED`; GAP-4) |
| NFR-S5 | Запрос профиля пользователя по ID не должен выполнять вход под этим пользователем. | Реализовано (переписывание бэкенда: вход — только через логин по токену; GAP-2) |
| NFR-S6 | Пользователи не должны иметь возможности изменять или удалять чужие аккаунты. | Реализовано (GAP-3) |
| NFR-S7 | API должно принимать запросы только с домена фронтенда. | Реализовано (CORS с `ALLOWED_ORIGINS`) |

## Производительность и нагрузка

| ID | Требование | Статус |
|---|---|---|
| NFR-P1 | Действие ведущего (переключение вопроса, показ ответов) должно доходить до всех игроков меньше чем за 1 секунду. | Реализовано для небольших групп (один процесс, состояние в памяти) |
| NFR-P2 | Система должна поддерживать не меньше 50 игроков в одной игре. | Реализовано (нагрузочная проверка 20×50, NFR-P5 — `backend/docs/load-test.md`) |
| NFR-P3 | Система должна поддерживать несколько игр одновременно. | Реализовано (этап 4a: комнаты по `sessionId`; GAP-1) |
| NFR-P4 | REST-запросы должны укладываться в клиентский таймаут 1 секунда. | Частично: 1 секунды может не хватить при холодном старте контейнера |

## Надёжность и данные

| ID | Требование | Статус |
|---|---|---|
| NFR-R1 | Живая игра должна переживать короткое отключение игрока или ведущего (переподключение в течение 30 секунд). | Реализовано (этап 4a: BR-58, BR-59 — переподключение с grace до 5 минут) |
| NFR-R2 | Перезапуск сервера не должен приводить к потере квизов. | Реализовано (PostgreSQL) |
| NFR-R3 | Удаление квиза должно удалять его вопросы и принимаемые ответы. | Реализовано (этап 2: внешние ключи с каскадным удалением; GAP-12) |
| NFR-R4 | Результаты игр должны сохраняться. | Реализовано (этап 5: GameSession и история игр; GAP-17) |

## Удобство использования

| ID | Требование | Статус |
|---|---|---|
| NFR-U1 | Экраном игрока должно быть удобно пользоваться на телефоне. | Реализовано (уточнено NFR-U5: от 360 px, проверено e2e) |
| NFR-U2 | Ошибки сервера должны показываться понятными сообщениями. | Реализовано (уточнено NFR-U6: JSON `{code, message}` с правильными HTTP-кодами) |
| NFR-U3 | Игроки должны иметь возможность подключиться по ссылке, не вводя ID. | Реализовано (этап 4a: ссылка-приглашение `/join/<sessionId>` и QR-код; GAP-11) |
| NFR-U4 | Квизы должны показываться по названию, а не по номеру. | Реализовано (этап 2; GAP-10) |
| NFR-U7 | Конструктором квиза можно пользоваться при ширине экрана от 360 px: без горизонтальной прокрутки, зоны нажатия не меньше 44 px, нижняя панель и FAB учитывают `env(safe-area-inset-*)`. | Реализовано ([документ 11](11-mobile-quiz-editor.md), e2e при 390 px) |

## Эксплуатация

| ID | Требование | Статус |
|---|---|---|
| NFR-O1 | Фронтенд разворачивается как статический сайт на GitHub Pages. | Реализовано |
| NFR-O2 | Бэкенд разворачивается как Docker-контейнер (Amvera) с миграциями базы данных. | Реализовано |
