# 8. Пробелы и бэклог

Пробелы, найденные при сравнении кода с требованиями из этого репозитория. Приоритеты:

- **P0:** нарушает честность игры или безопасность; исправить до показа продукта реальным пользователям.
- **P1:** основной пользовательский опыт.
- **P2:** качество и технический долг.
- **P3:** новые функции.

## Пробелы

| ID | Приоритет | Пробел | Последствия | Связано |
|---|---|---|---|---|
| GAP-2 | P0 | Пароли хранятся открытым текстом; cookie сессии — это ID пользователя в открытом виде; `GET /api/users/:id` выполняет вход под этим пользователем. **(закрыто переписыванием бэкенда: scrypt-хеши, непрозрачный токен, в базе — хеш)** | Любой, кто узнал ID пользователя (а ID рассылаются всем игрокам в живой игре), может действовать от его имени. | NFR-S1, NFR-S2, NFR-S5 |
| GAP-3 | P0 | Нет проверки владельца: любой пользователь может изменить или удалить любой квиз, вопрос, принимаемый ответ или аккаунт; любой WebSocket-клиент может отправлять сообщения ведущего (переключить вопрос, показать ответы, завершить игру). **(закрыто переписыванием бэкенда: `getOwned` на REST и проверка роли на WS-командах)** | Игрок может сорвать или завершить чужую игру. | FR-28, NFR-S3, NFR-S6 |
| GAP-4 | P0 | После каждого ответа сервер рассылает всем клиентам полное состояние игры, включая отметки «верно» или «неверно» для каждого игрока. **(закрыт этапом 4a: правильность только в `ANSWERS_REVEALED`)** | Игроки могут увидеть в инструментах разработчика браузера, кто ответил правильно, до показа ответов. | BR-34, NFR-S4 |
| GAP-5 | P0 | Игрок может отправить несколько ответов на один вопрос, пока ведущий не переключит вопрос; сервер сохраняет все ответы и засчитывает каждый правильный. **(закрыт этапом 4a: первый ответ считается, повторный — `CONFLICT`)** | Игрок может накрутить очки, отправив правильный ответ несколько раз. | BR-31, BR-35, FR-45 |
| GAP-1 | P1 | На сервере одна живая игра; все сообщения игры уходят всем подключённым клиентам. **(закрыт этапом 4a: комнаты по `sessionId`, рассылка только участникам)** | Два ведущих не могут проводить квизы одновременно. | BR-20, NFR-P3 |
| GAP-6 | P1 | «Add new question» сразу сохраняет пустой вопрос; кнопка «Start this quiz» доступна всегда. **(закрыт этапом 2)** | Квиз можно запустить с пустыми вопросами или вопросами без принимаемых ответов. | FR-27, US-8 |
| GAP-7 | P1 | Ответ сравнивается точно и с учётом регистра. **(закрыт этапом 3)** | `paris` считается неверным, если принимаемый ответ `Paris`; ведущему приходится перечислять все варианты написания. | BR-32, BR-64 |
| GAP-8 | P1 | Экран игрока игнорирует сообщения `END_GAME` и `FAULT`. **(закрыт этапом 4a)** | Игроки не узнают, что игра закончилась или что действие не удалось. | FR-48 |
| GAP-9 | P1 | Отключившийся игрок удаляется со всеми ответами; отключение ведущего завершает игру. **(закрыт этапом 4a)** | Перезагрузка страницы или слабый мобильный интернет стирают прогресс игрока. | BR-25, NFR-R1, FR-49 |
| GAP-10 | P1 | У квизов нет названий; в списке они показаны как «Quiz #1», «Quiz #2». **(закрыт этапом 2)** | Ведущий с несколькими квизами не может их различить. | FR-12, NFR-U4 |
| GAP-11 | P1 | «Copy link for the players» копирует просто ID игры; игроки вводят его вручную на главной странице. **(закрыт этапом 4a)** | Подключение медленнее и чревато ошибками, особенно с телефона. | NFR-U3 |
| GAP-12 | P2 | В интерфейсе нельзя удалить квиз; API удаляет запись квиза, но оставляет его вопросы и ответы. **(закрыт этапом 2)** | В базе остаются «осиротевшие» данные. | FR-13, NFR-R3 |
| GAP-13 | P2 | Порядок вопросов не задан явно (нет поля порядка), и его нельзя изменить. **(закрыт этапом 2)** | Порядок вопросов может отличаться от того, что ожидает ведущий. | FR-26, BR-11 |
| GAP-14 | P2 | API возвращает `401` или `404` на ошибки валидации и отдаёт сырые строки `Error: ...`. **(закрыт переписыванием бэкенда + этапом 6: `HttpExceptionFilter` отдаёт `{code, message, requestId}` с правильными HTTP-кодами, NFR-U6)** | Непонятные сообщения об ошибках; фронтенду трудно обрабатывать ошибки. | NFR-U2 |
| GAP-15 | P2 | Место игроков с равными очками в таблице победителей не определено. **(закрыт этапом 4b)** | Результаты могут выглядеть несправедливо. | BR-36, BR-72 |
| GAP-16 | P2 | Ни в одном репозитории нет автотестов и CI. **(закрыт этапом 6: unit-тесты в обоих репах, e2e-сьют, CI бэкенда и фронтенда)** | Регрессии находятся только вручную. | NFR-O3 |
| GAP-17 | P2 | Результаты игр не сохраняются. **(закрыт этапом 5)** | Ведущий не может посмотреть или выгрузить результаты после игры. | BR-26, NFR-R4 |
| GAP-18 | P1 | Конструктор квиза не приспособлен к узким экранам: фиксированная сетка `280px + 1fr`, адаптивных брейкпоинтов во фронтенде нет. **(закрыт — реализован по [документу 11](11-mobile-quiz-editor.md): нижняя навигация и FAB на <768 px)** | На телефоне (до ~500 px) название квиза, форма вопроса и кнопка запуска обрезаются — собрать или запустить квиз с мобильного нельзя. | NFR-U5, спецификация — [документ 11](11-mobile-quiz-editor.md) |
| GAP-19 | P2 | Экран ведущего живой игры (`grid-cols-[240px_1fr_240px]`) не приспособлен к узким экранам. | Вести игру с телефона нельзя: боковые панели сжимают вопрос и управление. | NFR-U5 |
